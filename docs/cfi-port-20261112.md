# lsdriver CFI/KCFI 迁移与崩溃定位

本轮对象是 `nbdriver`，设备 `192.168.1.4:41353`，内核为厂商
`6.6.30-酷安姜北尘`。源码排查和远程编译阶段未重新加载模块；
编译完成后的实机加载记录见下文。

## 实际证据

从设备只读保存的 `/sys/fs/pstore/console-ramoops-0` 位于
`out/crash-20261112/console-ramoops-0.txt`，SHA-256 为
`ef453085c21de18348854c935b91cce5709d8bbe9aba21da390f77928649b6b4`。
日志存在字节损坏，不能把损坏字符重写为原始证据，但其中能辨认出
`nbdriver_reboot_pre` 调用栈以及 CFI fatal exception。

旧模块 `out/dl-6.6/nbdriver-android15-6.6.ko` 的 SHA-256 为
`5134fc2a7defecb23fb1a18dba057d8030f1c7391eebf0fafdca6088a48c7339`。
反汇编确认 `nbdriver_reboot_pre+0xD0` 为 `brk #0x8229`，指令编码
`d4304520`，在通过函数指针调用 `task_work_add` 之前比较预期 KCFI
哈希 `0x0807B5FA`。pstore 可辨认出的陷阱指令与该片段对应。

此前“移动 euid 判断”的模块仍包含同一错误类型检查，位置移到
`nbdriver_reboot_pre+0xA4`。仅移动权限检查不能修复这个类型错误。

## 迁移范围

参考工作区 `lsdriver/export_fun.h` 和 `lsdriver/Makefile` 的 CFI 处理：

- 动态 kallsyms 与 task_work 调用在独立、禁止内联的函数中使用
  `no_sanitize("cfi", "kcfi")`，明确限定豁免调用点。
- task_work 函数指针使用 `__typeof__(&task_work_add)` 和 `TWA_RESUME`，
  避免把枚举参数简写成 `int`。
- 旧 CFI 构建识别与参考工程一致，通过 `CC_FLAGS_CFI` 启用。
  查找三个 slowpath 名称，使用 `aarch64_insn_patch_text` 同步写入
  `BTI C; RET X30`。这是旧分支的全局 CFI slowpath 行为变更。
- 新增原指令保存、重复地址去重、补丁失败回滚以及卸载恢复；缺少
  同步 patch API 时记录退化，动态调用仍使用局部豁免。
- 旧分支补齐缺失的 UBSAN CFI abort handler，处理方式与参考工程
  一样执行 `BUG()`，不会静默放过未被豁免的 CFI 失败。
- 保留 Kbuild 为模块回调生成的 CFI/KCFI 元数据。

这里迁移的是 CFI 处理部分；不迁移 lsdriver 的内存、断点、隐藏、
渲染业务，以及与当前调用无关的通用 ARM64 KCALL 汇编宏。

## 本地验证

`tests/kcfi_task_work_signature.c` 是只在用户态运行的故障复现。
使用 `clang-18 -O0 -Wall -Wextra -Werror -fsanitize=kcfi` 编译后：

| 调用 | 实际退出状态 |
|---|---|
| 内核声明推导出的准确签名 | 0 |
| 旧 int 签名直接调用 | SIGTRAP（subprocess returncode -5） |
| 局部 CFI 豁免调用 | 0 |

最小 AArch64 汇编实验中，旧签名的调用点预期哈希为 `0x0807B5FA`，
枚举签名为 `0x02A09238`。结果文件与反汇编位于
`out/crash-20261112/`。这些是用户态编译和运行证据，不能替代目标
模块在设备上的验证。

SDK 语法检查、ABI 头文件检查和 `git diff --check` 已通过。

## 目标设备加载与实际调用

使用 `adb -s 192.168.1.4:41353` 将上述原件推送至
`/data/local/tmp/nbdriver-cfi-b03910e-android15-6.6.ko`，设备上核对
SHA-256 一致，随后执行一次普通 root `insmod`，退出码 0。
设备内核日志报告 ksym、局部 CFI、reboot probe 均已就绪；
`/proc/modules` 显示 `nbdriver` Live。编译用户态静态测试工具，
调用 reboot 入口安装 FD、查询 ABI、检查错误返回、重新打开 16 次：
`device_ioctl_smoke: PASS`；ABI `version=2,size=16,features=0`。
操作前后 boot ID 均为 `8624d3fb-728a-4e07-b428-cabad0f98ea2`，
设备未重启，模块保持加载。原始输出、退出状态和卸载命令见
`out/device-cfi-load-20261112T135947Z/validation.json`。
这只验证加载及通信路径，不是长期稳定性测试，也不代表尚未实现
的驱动业务能力已可用。

## 备份与恢复

本轮修改前的文件和 SHA-256 清单保存在
`out/crash-20261112/before-cfi-port/`。该阶段已包含 task_work 类型修正；
进入本轮排查前的原始 reboot 文件另存于
`out/crash-20261112/before/nbdriver_entry_reboot.c`。
恢复这些备份文件，并移除本轮新增的 `src/nbdriver_cfi.c/.h` 及测试
文件，即可恢复迁移前源码。原 `.ko` 文件保持原件。
