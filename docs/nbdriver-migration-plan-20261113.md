# NBG-Draw-dfm → nbdriver 完整迁移计划

状态：计划。此次仅编写计划，不代表功能已实现或设备验证通过。
依据：当前 nbdriver 源码和 docs/nbg-draw-dfm-driver-usage-20261113.md 的业务调用清单。

目标是让 NBG-Draw-dfm 当前使用的非断点驱动能力逐步改由 nbdriver 提供，先打通进程读取，再补齐线程环境、解密所需元数据和输入能力。断点、观察点、shadow hook、寄存器注入和目标线程执行会话暂不迁移。

**当前基础**

- nbdriver 已有 reboot 入口 + task_work 安装匿名 FD + ioctl 通信、GET_ABI、进程读写和进程启动时间匹配字段。
- 当前 ABI 为 5。sdk/include/nbdriver.h 已按 LinyuKernel 方法直接写协议和函数，可独立复制使用。
- 单次内核读写上限为 64 KiB。NBG-Draw-dfm 现有封装允许单项 512 KiB，需适配。
- 当前普通读取可尝试补页，不能直接当成 readPresent 的实现。
- 前面已有的设备记录属于相应历史文件版本，不能用于证明后续新增能力。

**协议与接入约定**

1. 保留匿名 FD 通信。nbdriver 使用自己的命令号，不直接复用旧驱动的 socket ioctl 入口和认证扫描。
2. 现有 ABI 5、GET_ABI 和 48 字节读写结构保持布局与命令不变。新增功能使用新命令、独立结构和能力位；若未来确实需要破坏现有布局，再单独升级 ABI。
3. 内核协议和单头 SDK 的布局通过测试比较。公开 nbdriver.h 继续是手写、无类、无全局连接、无生成步骤的单头文件。
4. 内核负责通用进程/内存/输入功能；GetName/getUTF8 等应用数据解析留在用户态。
5. NBG-Draw-dfm 现有 c_driver/UnifiedDriver 作为应用适配层，内部改调用单头 C 接口，减少业务调用点改动。该类不放入 nbdriver.h。
6. 能力位必须反映实际可用性。缺失符号、内核配置或厂商支持时返回明确错误，不填伪造结果。
7. 每阶段同步交付内核实现、对应单头接口、适配说明和必要验证；旧驱动来源与版权信息随迁移记录保留。

**阶段 1：先让进程读取闭环跑通**

- 查 PID 按当前旧 OP_FIND_PID 的实际逻辑：精确匹配完整 argv[0]；多个候选按线程数、RSS、PID 排序。明确扫描/字符串边界，避免把 comm 当成完整包名。
- SO 原接口采用 basename/受限版本后缀匹配，并限定 vm_pgoff==0；扩展子串匹配留到阶段 10。
- 启动时间使用与现有 nbdriver 读写 expected_start_ns 一致的 start_boottime 单位和含义。
- 用户态先查身份，再携带该身份读取；PID 复用、目标退出或切换时失效旧状态。内核持有任务/mm 引用并遵循锁与释放规则。
- 验证既包含自写测试进程，也包含已提供目标的查询。定位成功后用已知地址/内容验证实际读取，不只打印“找到”。

**阶段 2：保留应用现有读取语义**

- readPresent 使用明确的不补页路径；不能由现有会尝试补页的普通读直接冒充。
- readFault 使用已解析且可用的补页能力，缺失时返回 EOPNOTSUPP 等明确错误。
- 批量读取保留每项状态。大请求拆成不超过 64 KiB 的内核块，全部使用同一预期进程身份；检查地址溢出与大小边界。
- 原始 C 接口保留 copied/error/failed_address。应用 bool read 的失败清零行为在适配层保持，不能丢掉内部诊断信息。
- GetName/getUTF8 复用现有用户态实现；不要为名称解析新增内核命令。现有写接口保留回归，当前应用未调用，不额外扩展写能力。

**阶段 3–5：恢复解密链路所需查询**

- 线程选择保留旧业务的 GameThread comm 查询规则，不默认选择最小 TID。
- TLS/APGA 标志分别检查。FPSR/FPCR 采样使用目标已保存且可稳定读取的状态，目标在 CPU 上或条件不满足时显式失败；本阶段不引入 Q0–Q31 或完整寄存器导出。
- maps 返回长度、容量与进程启动身份，处理路径转义、匿名映射和目标 exec/退出；页映射覆盖所支持的普通页/大页及权限。
- FD 使用有引用的目标文件对象读取元数据。GPU 查询只针对已有对象；厂商 KGSL 布局和内核符号必须有本次目标证据，不猜偏移。
- 随机读取保持原调用契约与大小限制，不通过目标线程执行来实现。

**阶段 6–9：输入和应用切换**

- 内存操作与触摸/陀螺仪通道分开管理，防止慢查询阻塞输入；明确状态锁与连接所有权。
- 槽位支持范围与应用现有请求一致，释放操作可重复调用；断开、初始化失败和退出都回收本连接持有的输入状态。
- 目标绑定使用有引用的 PID 对象或等效身份保护；nbdriver_target_bound_pid 作为内部辅助，不能只是缓存一个可能复用的整数。
- DEVPTS 查询与配置能力单独声明；按连接清理，避免一个只读 FD 的关闭停掉另一连接的配置。
- check_driver_available 基于新 FD + GET_ABI + 能力位；auto_initialize 更新适配层目标和身份；日志等级复用 nbdriver 日志设施。
- 旧 unhideFile 调用是清除旧模块规则，nbdriver 无法替另一个已加载模块撤销规则。切换前由旧模块清理，应用新路径移除无效调用或明确报告不适用，不伪造新驱动成功响应。
- 当前 unhideProcess 分支没有启用条件；进程/文件隐藏不作为新功能迁入。
- 应用按阶段 1 的最小识别、阶段 2 的读取、阶段 3–5 的解密、阶段 6–8 的输入/生命周期分批验证，不等全部完成才第一次编译。

**验证与交付规则**

- 每阶段先在源码副本上开发，保存原始 SHA256、差异、构建命令和实际输出；保留用户已有 tests/nbdriver_smoke.c 修改。
- 主机检查包括 C/C++ 独立单头编译、ABI 大小/偏移/ioctl 编码对照、必要的协议错误和应用适配检查。模拟调用通过不能替代内核行为测试。
- 内核检查沿用现有矩阵：android12-5.10、android13-5.10、android13-5.15、android14-5.15、android14-6.1、android15-6.6、android16-6.12、android17-6.18；核对未定义符号、KMI、CFI/KCFI 和构建日志。
- 设备先跑独立查询/读取探针，再跑应用；覆盖错误 PID/TID、同名进程、目标重启/退出、exec、容量不足、并发、反复打开关闭以及输入状态释放。
- 优先在已有匹配构建基础的设备分支做功能验证；其他 KMI 只构建通过时标记“构建通过、设备待验证”。没有设备连接时保留可运行探针和待验证清单。
- 最终交付对应版本的 nbdriver.h、源码差异、模块、应用构建产物、哈希、实际测试记录、已知限制和恢复方法。文件重新打开核对后交付；恢复验证使用额外副本，保留最终产物。

**里程碑**

A：阶段 0–2，通过“找到目标进程 → 查到 SO → 核对身份 → 读取已知数据”。
B：阶段 3–5，线程环境、映射与元数据具备，验证用户态坐标解密/PhysX 依赖。
C：阶段 6–9，输入与生命周期完成，应用切换到新驱动。
D：阶段 10–11，补齐查询扩展，完成构建矩阵、可用设备回归与最终交付。
